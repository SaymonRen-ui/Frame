## 1. Аккаунт и доступы

1. Нужен подтверждённый аккаунт разработчика в [RuStore Консоль](https://console.rustore.ru/).
   Для физлица — подтверждение личности, для ИП/юрлица — данные организации.
   Без пройденной проверки аккаунт не сможет публиковать приложения.
2. Роли в RuStore:
   - **добавлять новое приложение** может только **Владелец компании**;
   - загружать версии — Владелец, Администратор, Релиз-менеджер, Разработчик.
3. Если приложение добавляет не владелец аккаунта, заранее выдайте ему роль
   в разделе «Компания → Пользователи».

> Ключ `frame-release.jks` — главный актив проекта. Без него нельзя выпустить
> обновление: Android не установит APK с другой подписью. Держите минимум две
> резервные копии (офлайн-носитель + менеджер паролей). В git ключ не попадает —
> он закрыт `.gitignore`.

Проверьте **до** загрузки — это дешевле, чем получать отказ модерации.

- [ ] Нет тестовых данных, отладочных надписей и заглушек.

- [ ] Иконка в лаунчере выглядит нормально (в т.ч. под круглой маской).
- [ ] Ссылки из описания открываются: GitHub и `PRIVACY.md`.
- [ ] В кадре скриншотов нет статус-бара, рекламы и личных файлов.
- [ ] Название ≤ 30, короткое описание ≤ 80, полное ≤ 4000 символов.

Сборка и проверка:

```powershell
cd FrameAndroid

.\gradlew.bat :app:bundleRelease --offline

  app\build\outputs\apk\release\Frame.apk | Select-String "^package:"

& "$env:LOCALAPPDATA\Android\Sdk\build-tools\37.0.0\apksigner.bat" verify --print-certs `
  app\build\outputs\apk\release\Frame.apk
```

## 3. Создание приложения

1. Откройте [RuStore Консоль](https://console.rustore.ru/) → вкладка **Приложения**.
2. **Добавить приложение**.
3. Введите название: `Frame — читалка манги/комиксов` → **Добавить**.
4. Откройте созданную карточку → **Загрузить версию**.
5. Тип приложения — **Универсальный** (телефон/планшет). TV-версии у нас нет,
   поэтому галочки для ТВ не выбирайте.

Название должно быть уникальным в RuStore. Если занято — добавьте уточнение,
например `Frame — читалка CBZ/PDF` (24 символа), но не больше 30.

## 4. Загрузка версии

### Вариант А — APK (рекомендуется)

1. **Загрузить версию** → выберите `app/build/outputs/apk/release/Frame.apk`.
2. Дождитесь окончания загрузки, не закрывая страницу. Обработка может идти
   в фоне — можно сохранить черновик и вернуться позже.
3. Заполните параметры версии (раздел 5).
4. **Отправить на модерацию**.

Ограничения: файл до 5 ГБ, подпись обязательна, пакет уникален. Для обновлений
подпись и пакет должны совпадать, а `versionCode` — расти.

> Обработанные файлы хранятся в RuStore **14 дней**. Если не отправить версию
> на модерацию за это время, файл придётся загрузить заново.

APK — fat-сборка: внутри `arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64`.
Требование 64-бит выполнено, отдельные сплиты не нужны.

### Вариант Б — AAB

AAB подписывается вашим ключом загрузки, а RuStore проверяет сертификат и сам
подписывает собранные APK ключом подписи приложения. Поэтому в консоль нужно
загрузить **два файла**: ZIP с подписью и PEM-сертификат.

Понадобится Java 11+ (у нас JDK 17) и `pepk.jar`, скачанный из окна
**Загрузка подписи приложения**. `pepk.jar` должен лежать в той же папке,
из которой запускается команда.

**Шаг 1. Конвертировать `.jks` в `.keystore`** (RuStore просит формат
`.keystore`; содержимое то же):

```powershell
keytool -importkeystore `
  -srckeystore frame-release.jks `
  -destkeystore frame-release.keystore `
  -srcstorepass <storePassword> `
  -deststorepass <storePassword>
```

**Шаг 2. Сгенерировать ZIP с подписью.** В консоли нажмите **Загрузить**
напротив «Подпись не загружена» и скопируйте команду целиком: в ней уже есть
уникальный `encryptionkey`, менять его нельзя. Подставьте свои пути и alias:

```powershell
java -jar pepk.jar `
  --keystore=frame-release.keystore `
  --alias=frame `
  --output=pepk_out.zip `
  --encryptionkey=<ключ_из_консоли> `
  --include-signing-cert
```

Команда запросит пароль хранилища и пароль ключа — введите их вручную.
Получится `pepk_out.zip`.

**Шаг 3. Экспортировать сертификат ключа загрузки в PEM:**

```powershell
keytool -exportcert -alias frame -keystore frame-release.keystore `
  -rfc -file upload_cert.pem
```

**Шаг 4.** В окне консоли загрузите `pepk_out.zip` и `upload_cert.pem` →
**Отправить подпись**. Затем загрузите `app-release.aab`.

Требования: RSA не менее 2048 бит (у нас 2048), Java 11+.
Если ключ когда-нибудь потеряется — обновления станут невозможны; замена
подписи делается только через поддержку `support@rustore.ru` и перезаливку версий.

## 5. Карточка приложения

Все тексты — в `store/listing.txt`. Ниже что куда вставлять.

| Поле | Значение |
|---|---|
| Название | `Frame — читалка манги/комиксов` |
| Короткое описание | `Читалка манги и комиксов CBZ/PDF: библиотека, прогресс, история, офлайн` (71) |
| Полное описание | блок «ПОЛНОЕ ОПИСАНИЕ» (2008 символов) |
| Категория | **Книги и справочники** |
| Возрастная категория | **0+** |
| Поисковые теги | `манга`, `комиксы`, `читалка`, `CBZ`, `PDF` |
| Контакты | email `app.project@bk.ru`, сайт `https://github.com/SaymonRen-ui/Frame` |
| Иконка | `store/icon_512.png` |
| Скриншоты | 7 файлов `01-library.jpg` … `07-about.jpg`, вертикальные, телефон |
| Что нового | блок «ЧТО НОВОГО (версия 1.0.0)» |
| Политика конфиденциальности | ссылка на `PRIVACY.md` |

Детали:

- **Категория.** В RuStore выбирается одна категория. «Книги и справочники» —
  основная; «Развлечения» упомянуты в `listing.txt` как запасной вариант.
- **Возраст.** Начните с 0+: в приложении нет собственного контента, библиотеку
  загружает пользователь. Если модерация попросит — поднимите до 16+.
- **Теги.** Необязательны, до 5 штук. Не дублируйте название.
- **Контакты.** Достаточно одного поля, но лучше заполнить email и сайт.
- **Скриншоты.** От 3 до 10, до 3 МБ каждый, PNG/JPG, максимум 2160×3840.
  Наши 1080×1920 подходят, соотношение 9:16. Порядок загрузки = порядок файлов
  в папке, поэтому загружайте `01`…`07` по очереди.
- **Иконка.** 512×512, до 3 МБ, фон должен закрывать всю площадь — у нас
  непрозрачный RGB, это требование выполнено.
- **Что нового.** Для первой версии — список возможностей, а не «первый релиз»
  без деталей. Уже подготовлен в `listing.txt`.

## 6. Безопасность данных и разрешения

Консоль автоматически предзаполняет типы данных по разрешениям из манифеста.
Проверьте список и дополните вручную.

**Разрешения приложения:**

| Разрешение | Зачем |
|---|---|
| `INTERNET` | загрузка рекламы РСЯ |
| `ACCESS_NETWORK_STATE` | проверка сети перед запросом рекламы |
| `READ_EXTERNAL_STORAGE` (maxSdk 32) | чтение выбранной папки библиотеки на старых Android |
| `WRITE_EXTERNAL_STORAGE` (maxSdk 29) | доступ к `/sdcard/Frame` на Android 10 и ниже |

Ни камеры, ни микрофона, ни геолокации, ни контактов, ни фоновых сервисов.

**Что указать в «Категориях и типах данных»:**

- **Файлы и документы** — приложение читает CBZ/PDF и обложки из папки,
  выбранной пользователем. Обработка локальная, файлы никуда не отправляются.
- **Идентификаторы устройства** — рекламный ID и технические параметры
  обрабатывает рекламный SDK РСЯ.
- **Взаимодействие с приложением** — показы и клики по рекламе.

Если в форме есть поле «Обоснование» для доступа к файлам, используйте текст:
«Доступ только к папке библиотеки, которую пользователь выбирает сам через
системный диалог. Файлы читаются локально и не передаются на серверы».

Аккаунтов, аналитики, crash-репортинга и облака в приложении нет — это стоит
подчеркнуть в описании и политике.

## 7. Настройка публикации и модерация

1. **Настройка публикации**: приложение бесплатное, встроенных покупок нет.
2. Если консоль спросит про рекламу — отметьте, что приложение содержит
   рекламу РСЯ (баннер и полноэкранный блок).
3. Страна — Россия. СНГ можно добавить, но заполняемость рекламы за пределами
   РФ может быть ниже.
4. Режим публикации: автоматический (карточка появится сразу после одобрения)
   или ручной. Для первого релиза удобнее ручной — успеете проверить карточку.
5. Проверьте предпросмотр: название, иконка, скриншоты, описание, контакты.
6. **Отправить на модерацию**.
7. Статус и причина отказа появятся в карточке версии и придут на почту
   владельца аккаунта и контактный email. Срок зависит от текущей очереди —
   не перезаливайте версию, пока идёт проверка.

Типовые причины отказа и как мы их закрываем:

| Причина | Что делать |
|---|---|
| Приложение не запускается или падает | проверить чистую установку, выдать доступ к папке, открыть CBZ и PDF |
| Описание/скриншоты не соответствуют приложению | в кадре только реальные экраны, без обещаний из будущих версий |
| Реклама вне приложения или неожиданная | баннер только в библиотеке и истории, interstitial только при закрытии главы |
| Нет политики конфиденциальности | публичная ссылка на `PRIVACY.md`, проверить из режима инкогнито |
| Не обоснованы разрешения | текст из раздела 6 |
| Возрастной рейтинг не соответствует контенту | при замечании поднять до 16+ |
| Битая ссылка в описании | открыть GitHub и `PRIVACY.md` в браузере без авторизации |
| Прозрачные края иконки | у `icon_512.png` фон RGB по всей площади |
| На скриншотах статус-бар, реклама, личные данные | переснять/обрезать, демо-контент |
| Упоминание чужого бренда | при замечании заменить «в духе Mihon» на «в духе классических читалок манги» |

Если отказ непонятен — ответьте в тикете/письме модерации, приложите шаги
воспроизведения. Не создавайте дубликат приложения: это усложнит перенос
отзывов и установок.

## 8. После публикации

1. Откройте карточку в RuStore и установите приложение из магазина — проверьте,
   что реклама работает в release-подписи (в debug РСЯ не отдаёт блоки).
2. Проверьте, что ссылки и скриншоты отображаются на телефоне и планшете.
3. Отвечайте на отзывы через консоль.

### Как выпускать обновления

1. Поднимите версию в `app/build.gradle.kts`:
   ```kotlin
   versionCode = 2
   versionName = "1.0.1"
   ```
2. Соберите и подпишите тем же ключом:
   ```powershell
   .\gradlew.bat :app:assembleRelease --offline
   ```
3. В консоли: **Загрузить версию** → новый APK (или AAB) → заполните
   «Что нового» → **Отправить на модерацию**.
4. `versionCode` должен быть строго больше предыдущего, пакет и подпись — те же.
5. Не удаляйте старые версии из консоли без необходимости: они нужны для
   обновлений у пользователей.
